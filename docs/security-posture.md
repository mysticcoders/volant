# Security posture

How Volant's sandbox, helpers and permissions fit together. The [README](../README.md) has the summary.

- **App Sandbox on. No network entitlement.** The main binary has no network entitlement or telemetry. Sparkle checks and downloads updates through its dedicated helper. Opening links hands them to other apps. Shortcuts quicklinks hand execution to Shortcuts; those workflows may access the network or change data using their own permissions.
- **Optional local agent bridge.** Type `agents` or `herdr` in the launcher, or choose Agents from the menu, then Connect Herdr. The signed helper runs outside App Sandbox for Herdr discovery/focus and typed ACP conversations. Type `acp`, choose a project, and start OpenCode, Claude Code, or Codex; replies, tool status, cancellation and explicit permission choices appear in the main launcher. Providers use their own credentials, network access and tool permissions. No notes or clipboard history are sent automatically. Cursor’s ACP launch path is included but not verified on this machine; Claude Code and Codex use pinned adapters from the Agent Client Protocol project.
- **Listening servers.** Type `servers` or `ports` to list the local dev servers you're running, by port, runtime and folder; Return opens `http://localhost:<port>`. The sandboxed app can't see other processes' sockets, so the agent helper reads them through one read-only call that returns only the owner's own processes, never their arguments or environment, and acts on nothing.
- **No shell API; WASM extensions stay in a cage.** Extension code runs as a WebAssembly module inside a separate sandboxed XPC process, with only explicitly enabled, declared capabilities (see [extensions](extensions.md)). Extension code stays outside the app; the app handles and rechecks granted capability calls.
- **Two permissions, asked on first use:** Contacts and Calendar, each scoped by its own sandbox entitlement. Volant only reads, but note that Apple's Calendar grant is a full-access grant; the read-only behavior is the app's, not the OS's. Deny either and that feature simply returns nothing.
- **Camera and Automation of System Events, asked on first use of their commands only.** `com.apple.security.device.camera` lets Open Camera show a live, mirrored preview after you allow Camera access; macOS asks the first time you choose Open Camera, never at launch. The session runs only while the preview window is open, and nothing is recorded, saved or sent. The Apple Events entitlement is narrowed by a temporary exception to two apps: loginwindow, for the restart, shut down and log out confirmations, and System Events, which Toggle System Appearance and Toggle Menu Bar Hiding ask to flip `dark mode` or `autohide menu bar`. macOS asks for Automation consent the first time you choose one of them. No other app is automated, and a refusal shows a button to Privacy & Security. Pick Color uses macOS's own color loupe and needs no permission. See [system control](system-control.md).
- **No Input Monitoring grant, and no Accessibility grant unless you choose Type at the cursor or Search Menu Items.** Global hotkeys use Carbon `RegisterEventHotKey`, which needs no permission, and results are copied to the clipboard instead of pasted. Dictation can instead be typed at the cursor. Only then does Volant start `VolantInputHost`, a separate unsandboxed helper that asks once for Accessibility (listed as Volant), types only the phrases just dictated into the app that was in front, never reads that app's text, and refuses password fields and secure input. The opt-in Search Menu Items switch uses the same helper and grant to list the menu titles, shortcuts and enabled state of the app in front and press the one you choose, after re-checking that the same app is still in front; it never touches the Apple menu, Volant, the login window or password prompts, and the titles stay in memory only while the launcher is open. The helper's API is six calls (status, typing session begin/insert/end, list menu items, press a menu item): no key codes, no attribute names or element references from the app, and no reads of field or window text. The main app stays sandboxed and never uses Accessibility; `tools/check-input-confinement.py` keeps those APIs inside the helper. See [Search Menu Items](search-menu-items.md).
- **Clipboard history is AES-GCM encrypted at rest** with a 256-bit key held in the Keychain (`WhenUnlockedThisDeviceOnly`), stored in SQLite with `secure_delete` on, and excluded from Time Machine. Password-manager pasteboard markers (`ConcealedType`, `TransientType`, `is-sensitive`) are honored unconditionally. Supports text and images; PNG and TIFF copies are stored as PNG, capped at 8 MB per image.
- **Release builds are meant to be Developer ID signed, hardened, notarized and stapled** by `Scripts/release.sh`, which now refuses to package an archive that carries debugger access or a network entitlement or lacks a Developer ID signature. Local builds from `install.sh` are development-signed and not notarized; Volant 0.1.2 (build 4) has passed Apple notarization. Sparkle and Check for Updates are integrated; a two-version installed upgrade test remains pending. See [release quality and setup](release-quality.md).
- **One dependency: Sparkle**, for updates. Otherwise AppKit, SwiftUI, Carbon, CryptoKit, SQLite3 and Security. Project generated by xcodegen.

## Not included, by choice

Window management and window search, which would need Accessibility in the main app; that stays ruled out. Menu-bar search exists only as the opt-in Search Menu Items command, done by the separate input helper, never by the main app. Add deliberately.
